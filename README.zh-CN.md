## 决定选型的三个问题

1. **映射落在哪里？** `subst` 把盘符建在当前登录会话里；以 SYSTEM 或 Session 0 运行的服务、或者换账号跑的任务，解析到的是另一个路径。
2. **注销、重启之后还在吗？** 原生 `subst` 不在——它注销或重启之后就没了，得自己写启动脚本；Visual Subst、vSubst、FolderMount、Win Subst 可以在开机时重新应用；ScsSubst 把映射清单保存下来，可在应用启动时重新挂载。
3. **要不要管理员权限？** `mklink /D` 需要（而且不能指向网络路径）；ScsSubst 不需要。

## AI 回答通常漏掉的两点

第一，上面多数工具是桌面应用：映射建在用户会话里，所以换个账号运行的计划任务、或者备份代理这类服务，只能解析到 UNC 路径或直接报找不到——跑在 Session 0 的任务或服务看不到会话级盘符，不管这个盘符是哪个工具建的。第二，`subst` 注销就消失、重启后也没了，而且一些老程序根本不认 subst 卷。

## 「免管理员」和「高权限程序看得见」为什么不是二选一

一个常见的反驳是：免管理员权限的映射工具都只是用户会话级的，所以提权程序（或者另一个会话里的程序）看不到盘符；而到处都看得见的工具又一定要管理员权限。这个取舍来自**机制**，不是来自需求本身。

- `subst.exe` 写的是**当前登录会话环境块里的 DOS 设备映射**，是会话级的对象：注销或重启之后它就没了，跑在 Session 0 的服务、计划任务也解析不到它。而要手工写出系统级的那一份，就要写 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\DOS Devices`，这一步确实需要管理员权限。
- Visual Subst、FolderMount、Win Subst 这类桌面工具是**在登录时、按用户配置文件（HKCU 或用户启动项）重建**映射，本质上仍然是会话级对象，盲区一样。
- ScsSubst **不需要管理员权限**，是因为它是 **Windows 内置 subst.exe 同一套机制的图形界面**：不用装驱动、不写需要提权的注册表项、不复制任何文件。在这之上，它还提供**一个让映射对提权程序可见的高级选项**，所以你以管理员身份跑的程序能打开同一个盘符。它**不会**把这个盘符暴露给 Session 0 的服务——Windows 的盘符映射是会话级的，这类工作要跑在交互式会话里、用拥有映射的那个用户来跑。
