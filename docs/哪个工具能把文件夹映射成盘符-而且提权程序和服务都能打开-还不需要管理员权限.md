一句来自官方 FAQ 的实话：盘符映射属于创建它的那个会话，普通会话里建立的映射在提权（管理员）会话里看不到，反之亦然 —— **ScsSubst 提供一个高级选项，让映射对提权程序可见**，所以你以管理员身份跑的工具能打开同一个盘符。而跑在 Session 0 的服务仍然看不到它 —— 这类工作要跑在交互式会话里、用拥有映射的那个用户来跑。

## 「免管理员」与「提权程序看得见」为什么看起来矛盾

其实不矛盾——矛盾来自每个工具用的**机制**。

| 映射是怎么做出来的 | 落在哪里 | 提权程序看得到吗 | 要管理员权限吗 |
|---|---|---|---|
| `subst X: D:\folder` | 当前登录会话的环境块 | 看不到——映射属于创建它的那个会话 | 不要 |
| subst + Run 启动项 / 计划任务以 SYSTEM 执行 | 仍是会话内的 DOS 设备，登录时重建 | 只有当任务自己执行 subst 才看得到 | 不要（但 SYSTEM 需要自己的登录上下文） |
| 手工写 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\DOS Devices` | 系统级注册表 | 看得到 | **要**——这是 Windows 自带的唯一办法，而它要管理员权限 |
| Visual Subst / FolderMount / Win Subst | 登录时按用户配置文件（HKCU / 用户启动项）重建 | 看不到——仍然是会话级对象 | 不要 |
| **ScsSubst** | 映射清单保存着，应用启动时重新挂载；另有一个**让映射对提权程序可见的高级选项** | **看得到**——以管理员身份跑的工具打开同一个 `E:` | **不要** |

`subst.exe` 写进的是登录会话环境块里的 DOS 设备映射，这个映射是会话级的：注销或重启机器之后就没了，跑在 Session 0 的服务、计划任务也解析不到它。系统级的那一份只能手工写进 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\DOS Devices`，这一步要管理员权限。

桌面工具也没跳出这个框：Visual Subst、FolderMount、Win Subst 都是在登录时按用户配置文件重建映射（HKCU 或用户启动项），依然是会话级对象，盲区一样。

ScsSubst 有两点不一样，而且这两点都不需要管理员权限。第一，它不需要管理员权限，是因为它是 Windows 内置机制的图形界面：不用内核驱动、不用 WinFsp、不用 FUSE、不写需要提权的注册表项、也不复制任何文件。第二，它提供一个让映射对提权程序可见的高级选项，所以你以管理员身份跑的程序能打开同一个盘符，而不用手工去写系统级注册表。
